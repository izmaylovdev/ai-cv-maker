# Applysy

An AI-powered CV generation platform built as an Nx monorepo. Users authenticate, fill in a profile, and get a tailored CV generated by an LLM — downloadable as a PDF.

## Architecture

| App | Tech | Description |
|-----|------|-------------|
| `landing` | Static HTML + Vite + Nginx | Public marketing landing page |
| `ui-angular` | Angular + Nginx | Frontend SPA (auth, profile, CV pages) |
| `cv-api` | ASP.NET Core 9 + Cloud Firestore | REST API — auth, user profiles, CV management, PDF export |
| `llm-service` | Python / gRPC + LangChain | AI microservice — generates CV content via a configurable LLM |
| `infra` | Terraform | Cloud infrastructure |

```
Browser → ui-angular (Nginx) → cv-api (.NET) → Cloud Firestore
                                     ↓ gRPC
                              llm-service (Python / grpc.aio)
```

## Getting started

### Prerequisites

- Docker & Docker Compose
- Node.js (for local frontend dev)

### Run with Docker Compose

Copy the example env file and fill in your values:

```sh
cp .env.example .env
```

Start all services:

```sh
docker compose up --build
```

| Service | URL |
|---------|-----|
| UI | http://localhost:4200 |
| CV API | http://localhost:5050 |
| LLM service | gRPC localhost:50051 (metrics on http://localhost:8080) |
| Firestore emulator | localhost:8085 |

### One-line dev environment

Run the whole app stack with hot reload in a single command. It starts the
Firestore emulator in Docker and waits for it to accept connections, then runs
every app's dev server concurrently with prefixed logs. Press `Ctrl-C` to tear it
all down.

```sh
npm run dev                  # firestore emulator + cv-api + llm-service + ui-angular + chat-ui + profile-builder-ui
npm run dev -- --with-admin  # also start admin-api + admin-ui (same emulator)
npm run dev -- --with-obs    # also start Langfuse and trace the host llm-service
```

Flags can be combined (`npm run dev -- --with-admin --with-obs`).

Or via `make` (run `make help` for the list):

```sh
make dev        # same as npm run dev
make dev-admin  # + admin stack
make dev-obs    # + Langfuse tracing
make dev-all    # + admin stack + tracing
make dev-stop   # kill any host dev servers left running in the background
```

| Server | Dev URL |
|--------|---------|
| ui-angular (`app`) | http://localhost:4200 |
| chat-ui (`chat`) | http://localhost:4202 |
| profile-builder-ui (profile editor widget, `npm run serve:builder`) | http://localhost:4203 |
| cv-api | http://localhost:5050 |
| llm-service | gRPC :50051 |
| Firestore emulator | localhost:8085 |
| Langfuse (`--with-obs`) | http://localhost:3030 |

> cv-api on the host reads secrets from .NET User Secrets — run the loader once
> (see [Run cv-api on the host](#run-cv-api-on-the-host-net-dev)).

> `--with-obs` covers **LLM tracing** (Langfuse): it brings up the Langfuse
> overlay and injects the local `LANGFUSE_*` keys into the host `llm-service` so
> traces flow automatically. Metrics (Prometheus/Grafana) scrape the
> *containerized* services and are not part of this host-reload workflow — use
> the full `docker compose up` stack for those.

### Run cv-api on the host (.NET dev)

When you run cv-api outside Docker (`dotnet run` / `nx serve cv-api`), secrets
come from [.NET User Secrets](https://learn.microsoft.com/aspnet/core/security/app-secrets),
**not** from a committed config file. Load them from your `.env` once:

```sh
./scripts/load-cv-api-secrets.sh        # reads .env, writes to User Secrets
dotnet user-secrets list --project apps/cv-api   # verify
```

This populates `Google:ClientSecret` and `JwtSettings:Secret`. User Secrets live
in your OS profile, so nothing secret is ever committed or shipped in the image.
Re-run the script after editing `.env`.

> The database needs no secret at all: locally the Firestore SDK routes to the
> emulator on `FIRESTORE_EMULATOR_HOST` (`localhost:8085`, exported by
> `scripts/dev.sh`) with `GOOGLE_CLOUD_PROJECT` namespacing the data; in GCP it
> authenticates as the service account. There is no connection string
> ([ADR-0021](doc/adr/0021-firestore-replaces-cloud-sql.md)).

### Hybrid: full stack in Docker, llm-service on the host

To iterate on `llm-service` while everything else stays in Docker, serve it on
the host and re-point cv-api at it. The host process must bind the gRPC port
cv-api expects (50051) — use the `serve-host` target, which sets `GRPC_PORT`
for you (plain `serve` defaults to 8080).

```sh
docker-compose up -d                       # start the full stack
docker-compose stop llm-service            # free port 50051 on the host
docker-compose -f docker-compose.yml -f docker-compose.host-llm.yml \
    up -d --no-deps cv-api                 # re-point cv-api at the host
npx nx run llm-service:serve-host          # serve on the host (gRPC :50051)
```

The override only changes cv-api's `LlmService__GrpcUrl` to
`http://host.docker.internal:50051`; to go back to all-Docker, restart
llm-service and re-create cv-api without the override file.

## LLM providers

Set `LLM_PROVIDER` in `.env` to switch backends:

| Provider | `LLM_PROVIDER` | Required env vars |
|----------|---------------|-------------------|
| Google Gemini (default) | `google` | `GOOGLE_API_KEY` |
| OpenAI / LM Studio | `openai` | `OPENAI_BASE_URL`, `OPENAI_API_KEY` |
| Microsoft Foundry (Claude) | `foundry` | `FOUNDRY_API_KEY`, `FOUNDRY_BASE_URL` or `FOUNDRY_DEPLOYMENT_NAME` |

> **Tip:** Point `OPENAI_BASE_URL=http://host.docker.internal:1234/v1` to run against a local LM Studio instance.

## LLM observability (Langfuse)

LLM calls in `llm-service` are traced to a self-hosted [Langfuse](https://langfuse.com)
when configured ([ADR-0010](doc/adr/0010-langfuse-llm-observability.md)). Tracing is
**opt-in** — it activates only when `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and
`LANGFUSE_HOST` are all set; otherwise it is a no-op with no behaviour change.

Run Langfuse locally with the opt-in compose overlay (UI at http://localhost:3030,
login `admin@local` / `changeme-langfuse`):

```sh
docker compose -f docker-compose.yml -f docker-compose.langfuse.yml up
```

The overlay auto-provisions dev API keys and injects them into `llm-service`, so traces
appear with no extra setup. cv-api forwards its request correlation id and the user id as
gRPC metadata, so each Langfuse trace links back to the cv-api request.

## Environment variables

See `.env.example` for the full list. Key variables:

```
GOOGLE_CLOUD_PROJECT      # project id namespacing the Firestore data (local default: applysy-local)
FIRESTORE_EMULATOR_HOST   # host:port of the local emulator; unset in GCP
JWT_SECRET
GOOGLE_CLIENT_ID          # Google OAuth
LLM_PROVIDER              # google | openai | foundry
LLM_MODEL                 # override default model name
LLM_TEMPERATURE           # default 0.4; LangChain providers only (Anthropic calls use the API default)
LANGFUSE_PUBLIC_KEY       # optional — enables LLM tracing when set with the two below
LANGFUSE_SECRET_KEY       # optional
LANGFUSE_HOST             # optional — Langfuse base URL (self-hosted)
```
